## 01 · Repositorio y publicación

### Nivel 1 · No cumple

- [ ] El repositorio es público.
- [ ] El sitio está accesible en Vercel.

**Nivel 1:** alcanza cuando falla al menos uno de los dos puntos anteriores.

### Nivel 2 · Cumple

- [ ] El repositorio es público.
- [ ] El sitio está accesible en Vercel.

**Nivel 2:** alcanza cuando se cumplen ambos puntos.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] La presentación del repositorio incluye una descripción del proyecto.
- [ ] El repositorio incluye acceso directo al sitio publicado.

---

## 02 · README obligatorio

### Nivel 1 · No cumple

- [ ] Incluye una descripción del proyecto.
- [ ] Incluye el enlace al deploy.
- [ ] Incluye los nombres de todos los integrantes.
- [ ] Incluye los enlaces a los perfiles de GitHub.

**Nivel 1:** no se alcanza si falta alguno de los elementos obligatorios.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Los cuatro elementos están completos.
- [ ] Los enlaces funcionan correctamente.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] El README incluye un índice con enlaces internos.
- [ ] El README incluye capturas del proyecto.

---

## 03 · Integrantes con acceso al repositorio

### Nivel 1 · No cumple

- [ ] Todos los integrantes tienen acceso aceptado al repositorio.

**Nivel 1:** no se alcanza si falta al menos un integrante con acceso.

### Nivel 2 · Cumple

- [ ] Todos los integrantes tienen acceso.
- [ ] El propietario del repositorio cuenta como integrante con acceso.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] El README identifica la responsabilidad de cada integrante.

---

## 04 · Proyecto desarrollado en React

### Nivel 1 · No cumple

- [ ] La aplicación está desarrollada en React.
- [ ] React se utiliza realmente para construir la aplicación.

> Instalar la dependencia de React sin utilizarla no alcanza este nivel.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La aplicación utiliza React.
- [ ] Las pantallas se renderizan mediante componentes.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Se reutiliza un mismo componente con distintos datos mediante `props`.

---

## 05 · Sidebar compartida

### Nivel 1 · No cumple

- [ ] Existe una sidebar.
- [ ] Incluye la identidad del equipo.
- [ ] Incluye enlaces funcionales.
- [ ] Permite identificar la ubicación actual.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La sidebar es compartida entre las diferentes secciones.
- [ ] Muestra la identidad del equipo.
- [ ] Sus enlaces funcionan.
- [ ] La sección activa está identificada.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] La sidebar se adapta correctamente a dispositivos móviles.
- [ ] En móvil funciona mediante un panel que puede abrirse y cerrarse.

---

## 06 · Navegación completa

### Nivel 1 · No cumple

- [ ] Ninguna pantalla queda sin una salida interna.
- [ ] Ninguna pantalla exige utilizar el botón Atrás del navegador.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Todas las pantallas permiten continuar mediante controles de la aplicación.
- [ ] Todas las pantallas permiten volver mediante controles de la aplicación cuando corresponde.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Se puede abrir directamente la URL de cada sección.
- [ ] Se puede recargar directamente la URL de cada sección sin errores.

---

## 07 · Portada del equipo

### Nivel 1 · No cumple

- [ ] La portada no se limita a un listado o conjunto de perfiles.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Presenta al equipo.
- [ ] Incluye el nombre del equipo.
- [ ] Incluye una descripción.
- [ ] Permite acceder a los perfiles.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] La presentación visual está cuidada.
- [ ] Incluye elementos interactivos que introducen al equipo.
- [ ] Los elementos interactivos permiten acceder o conocer los perfiles.

---

## 08 · Perfiles dentro de React

### Nivel 1 · No cumple

- [ ] Existe un perfil para cada integrante.
- [ ] Todos los perfiles funcionan.
- [ ] Los perfiles forman parte de la aplicación React.
- [ ] Los perfiles no son simplemente enlaces a páginas del TP1.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Todos los integrantes tienen un perfil funcional dentro de la aplicación React.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Todos los perfiles incluyen una interacción funcional sobre su contenido.

---

## 09 · Apropiación y propuesta estética

### Nivel 1 · No cumple

- [ ] La aplicación tiene estilos aplicados.
- [ ] La presentación permite leer y utilizar correctamente el sitio.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La aplicación tiene una presentación funcional.
- [ ] La propuesta estética puede ser genérica.
- [ ] Si se utilizó IA para la propuesta visual, existe una personalización visible de ese resultado.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Existe una paleta visual definida.
- [ ] Existe una elección de tipografías.
- [ ] La composición mantiene una identidad consistente.
- [ ] Los recursos visuales son coherentes con la propuesta.
- [ ] La identidad visual representa al equipo.

### Nivel 4 · Supera

Además de cumplir los niveles anteriores:

- [ ] Existe una propuesta estética integral para el equipo.
- [ ] Se utilizan imágenes generadas o editadas específicamente para el proyecto.
- [ ] La composición está personalizada.
- [ ] Existe coherencia visual entre portada, perfiles y demás secciones.

---

## 10 · Datos locales JSON

### Nivel 1 · No cumple

- [ ] Existe un archivo JSON local.
- [ ] Contiene al menos 20 registros.
- [ ] Los datos se muestran dinámicamente.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] El JSON contiene al menos 20 registros.
- [ ] Los registros están relacionados con la propuesta del proyecto.
- [ ] Los registros se muestran dinámicamente en la aplicación.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Cada registro permite desplegar o consultar información adicional.

---

## 11 · Búsqueda y filtro

### Nivel 1 · No cumple

- [ ] Existe una búsqueda por texto.
- [ ] Existe un filtro.
- [ ] La búsqueda modifica correctamente los resultados.
- [ ] El filtro modifica correctamente los resultados.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La búsqueda por texto funciona sobre los datos locales.
- [ ] El filtro funciona sobre los datos locales.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Se informa claramente cuando no existen resultados.
- [ ] Existe una forma de restablecer la lista completa.

---

## 12 · API pública y estados

### Nivel 1 · No cumple

- [ ] Se consume una API pública.
- [ ] Se muestran sus resultados.
- [ ] Existe un estado de carga.
- [ ] Existe un estado de error.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La aplicación consume una API pública.
- [ ] La aplicación muestra los resultados obtenidos.
- [ ] Se implementa un estado de carga.
- [ ] Se implementa un estado de error.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] La interfaz permite actualizar la consulta.
- [ ] La interfaz permite reintentar la consulta cuando corresponde.

---

## 13 · Árbol de renderizado

### Nivel 1 · No cumple

- [ ] Existe un árbol de renderizado.
- [ ] El árbol corresponde a los componentes reales del proyecto.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Se incluye una imagen o esquema estático.
- [ ] Representa la jerarquía real de componentes.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] El árbol permite expandir sus componentes.
- [ ] El árbol permite contraer sus componentes.

## 14 · Bitácora

### Nivel 1 · No cumple

- [ ] Existe una sección de bitácora.
- [ ] La bitácora contiene registros del proceso.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] La bitácora contiene registros del proceso de trabajo del equipo.
- [ ] Los registros son accesibles dentro de la aplicación.
- [ ] La sección funciona correctamente.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Los registros se presentan mediante elementos desplegables o equivalentes.
- [ ] Existen filtros funcionales para consultar los registros.

---

## 15 · Declaración de uso de IA

### Nivel 1 · No cumple

- [ ] El proyecto declara el uso de IA.
- [ ] Se identifica la aplicación utilizada.
- [ ] Se identifica el modelo utilizado.

**Nivel 1:** no se alcanza si no se declara el uso de IA, si sólo se menciona la aplicación o si sólo se menciona el modelo.

### Nivel 2 · Cumple

Además de lo anterior:

- [ ] Se identifica la aplicación utilizada.
- [ ] Se identifica el modelo utilizado.

### Nivel 3 · Propone

Además de cumplir el nivel 2:

- [ ] Se identifica la aplicación utilizada por cada integrante.
- [ ] Se identifica el modelo utilizado por cada integrante.
- [ ] Se indican los contenidos o tareas para los que se utilizó IA.
